# DocumentHub — exploratory test report

**Date:** 5 Nov 2026 · **Build:** production bundle (`npm run build`) in Electron 45 on macOS · **Method:** scripted exploratory session with real files on disk (corrupt, legacy, styled, multi-sheet, HEIC, TIFF, 12 MP JPEG, CSV with `;` and BOM), plus code inspection where a behaviour can't be triggered headlessly.

**Result:** 47 probes run. 26 passed and 21 failed. Some failures are bugs and some are missing features.

## Critical: data loss

| # | Bug | Steps to reproduce | Evidence |
|---|---|---|---|
| 1 | **Saving an existing .docx strips its formatting.** The header, footer, font sizes, colours and font names are removed. Save now overwrites the original file in place, so one Cmd+S permanently damages the user's document. | Open a styled .docx → type one character → Cmd+S | After saving: header kept = no, red colour kept = no, 28 pt kept = no, Georgia kept = no (11,321 B → 9,908 B). The editor never displays them either: a 28 pt red title renders as 11 pt black. |
| 2 | **Unsaved work is discarded without warning.** Closing a tab, closing the window or pressing Cmd+Q never asks. Tabs and the window title don't show an unsaved marker. | Edit any document → click × on its tab | Tab closes immediately and the edits are lost. Title stays "DocumentHub". |
| 3 | **Files that fail to open stay open as empty tabs.** Pressing Save would overwrite the original file with an empty document. | Open corrupt.pdf, corrupt.docx or legacy.doc | Error toast is shown correctly, but a blank tab remains for each file. |
| 4 | **Theme, background or slide changes delete speaker notes.** Applying a theme, setting a background, or adding/reordering slides in an opened .pptx rebuilds the deck, which drops the notes. The warning wrongly says "slides were added/reordered". | Open a deck with notes → Design → Theme → Save | Notes text kept = no. |

## Passed

- **Robustness:** unsupported file types are rejected with a clear message.
- **PDF:** all pages render; edit text, rotate, delete and save in place work with no dialog; undo restores a deleted page; print keeps each page's size.
- **Word:** a `.txt` saved as `.docx` asks first and leaves the `.txt` untouched; printing works.
- **Excel:** saving in place keeps merges, formats and formulas in the file.
- **PowerPoint:** opening a deck with a picture works; Backspace while typing doesn't delete the text box; saving a text edit in place keeps speaker notes; profile photos (several at once, circular); background picture; theme; export to PDF.
- **Images:** a 12 MP JPEG rotated and saved in place stays JPEG; iPhone HEIC opens; TIFF opens; OCR works in the packaged build (54 words found).

## Not covered

- Password-protected PDFs (no tool on this machine could create one).
- Printing on real paper (the print dialog was intercepted in the test).
- Windows, iOS and Android devices.
- Very large documents (100+ pages).
- OCR without an internet connection.

## Investigated, not a bug

- **Slide running off the right edge (user screenshot):** couldn't reproduce at 1325 × 760, after resizing, after switching tabs, or after resizing while hidden. The slide always fits its area. The screenshot looks cropped on the right and bottom.

## Re-test after fixes (same day)

All 22 bugs above are fixed. Each one was re-checked with the same exploratory probes on the production build, which now includes the Content-Security-Policy. The automated suite (`npm test`, 23 tests) adds a regression test for each fix.

| # | Fix | Verified by |
|---|---|---|
| 1 | Word files are read directly with a new importer, so fonts, sizes, colours, highlights, lists, tables, sized images and headers/footers are kept. On save, the original headers, footers and page setup are copied into the new file. | C1–C3 plus round-trip test: 28 pt red Georgia, header and landscape page all kept |
| 2 | Unsaved changes show a ● on the tab and in the window title. Closing a tab or quitting asks Save / Don't Save / Cancel, and quitting offers Save All. | G1, G2, G4 |
| 3 | A file that fails to open no longer leaves a tab behind. | A1–A3 |
| 4 | Every PowerPoint edit, including slide add/duplicate/delete/reorder, backgrounds, themes and new shapes or pictures, is written into the original file, so speaker notes, masters and animations are kept. | E3, E6, plus test with notes on reordered and deleted slides |
| 5 | Cover and Edit text now remove the covered glyphs from the PDF itself. Removed glyphs are replaced by equal-width gaps, so the remaining text doesn't move. | B4, plus redaction test checking the text is gone and the layout unchanged |
| 6 | PDF → Word works on rotated pages. | B7 |
| 7 | Double-clicking a document in Finder or Explorer, or using "Open With", opens it; if the app is already running, the file opens there. The app also has a native File menu. | Packaged app launched with a PDF and showed it as a tab |
| 8 | Keyboard shortcuts keep working after printing. | C8 |
| 9 | New formula engine (no runtime code evaluation): cross-sheet references, VLOOKUP/INDEX/MATCH, SUMIF/COUNTIF, IFERROR and more. Formulas it doesn't support show the value Excel saved. | D4 plus formula test |
| 10 | Phones: a 📄 Pages drawer for PDF page tools, and menus always stay on screen. | B8–B10 |
| 11 | Number, percentage, currency and date formats are displayed, using the system locale. | D1–D3 |
| 12 | Merged cells are displayed merged. | D5 |
| 13 | Long words wrap in Word → PDF, which also keeps each run's font size and font family. | C4 plus test |
| 14 | Undo/redo in the spreadsheet and presentation editors. | D8, E7 |
| 15 | Opening a file that's already open switches to its tab. | B2 |
| 16 | Moving around a sheet no longer adds rows. | D6 |
| 17 | Word editor has font and size controls. | C7 |
| 18 | Sheets can be renamed (double-click a tab), moved and deleted. | D9 |
| 19 | CSV import reads German number and date formats. | D10 plus test |
| 20 | Slide thumbnails show the real slide content. | E9 |
| 21 | Profile-photo captions adjust to the background (white on dark slides). | Code review plus screenshot |
| 22 | Content-Security-Policy is set in production builds. iPhone (HEIC) photo decoding moved to a WebAssembly decoder (libheif), because the old decoder needed `eval`. | G5, F2 |

**Still not covered:** password-protected PDFs, real paper printing, Windows, iOS and Android devices.
